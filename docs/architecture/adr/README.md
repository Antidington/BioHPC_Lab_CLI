# Architecture Decision Records

Create a record when a material architectural decision needs lasting context.
Use sequential names such as `0001-use-example-database.md`. Proposed records
may evolve. Preserve accepted rationale; lifecycle status and superseding
links may be updated. Record a substantive replacement decision in a new ADR.

A proposed ADR does not itself authorize implementation or external actions.

## Template

```markdown
# ADR-NNNN: Decision title

- Status: Proposed | Accepted | Superseded | Rejected
- Date: YYYY-MM-DD
- Owners: TODO

## Context
## Decision
## Consequences
## Alternatives considered
## Supersedes or is superseded by
```
